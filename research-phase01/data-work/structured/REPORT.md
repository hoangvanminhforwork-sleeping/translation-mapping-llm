## 6. What is missing, and why

* **The three 'American' PDFs are not the books.** `us_american_cuisine` and `us_food_younger_land` are Bookey study-guide summaries (31 and 70 pages of condensed chapter digests); `us_sioux_chef` is a 2-page publisher blurb. Their facts are what the *summary* states, with Bookey's own prose as the quote — they must be cited as secondary/marketing sources, never as Freedman or Sherman. `provenance.ocr_model` records this and the `book` slug keeps them separable. The Sioux Chef blurb yields 0 facts: it contains no quotable atomic factual claim, only marketing copy.
* No American *recipes* were extracted: the summaries contain no ingredient lists or procedure, and `us_sioux_chef` has no recipe text at all.
* 212 candidate facts were dropped for failing the substring test. Inspecting them: most are sentences that straddle an OCR page break (the book splits one sentence across two PDF pages) or spans where the model repaired a garbled OCR word. The verifier is per-page by design, so these are dropped rather than accepted on trust.
* TOC front matter (pages 1-7) is OCR-garbled at the glyph level (`MÓN`→`MÔN`, `LƯƠN`→`Lương`), so recipe titles come from the body heading, not the TOC. One heading survives with OCR case damage: `MIỀN Lươn` (should be `MIỀN LƯƠN`).
* Recipe rows inherit the book's prose style: ingredients are often inside sentences ("Tẩm ướp với: ..."), so `ingredients` mixes one-line list items with clause-level extractions of the same sentence. Nothing was added that is not on the page, but counts of ingredients per recipe are not comparable across dishes.
* `directions` are verbatim-ish sentences, not normalised imperative steps; RecipeNLG consumers expecting one-action-per-step strings must post-process.
* `subject` is often a descriptive noun phrase rather than a clean entity (`Thịt lợn thăn thái mỏng, vắt chanh (hay nhúng dấm)`), because the source writes that way. Claims are atomic, but entity resolution / dish-name linking is left to the downstream stage.
* The brief said the recipe book holds ~100 recipes; its own TOC lists 167 entries between pages 8 and 223, and all 167 were extracted. The TOC, not the brief, is treated as ground truth.
* Some facts are only weakly 'culinary' (e.g. the origin of the word *Bodega*, a folk poem about persimmons in September). They are kept when the page makes the claim, because the `category` field lets downstream filtering discard them; they are not silently dropped.
* `facts.db` is rebuilt from scratch on every run (`DROP TABLE IF EXISTS` + `CREATE`), so re-running stage 3 is idempotent and never duplicates rows.
* Page numbers in the JSONL are the `<!-- page N -->` **marker** numbers, not the printed folio (in `vn_van_hoa_am_thuc` the offset is +3 near the start, e.g. marker 40 = printed 43).

## 9. How to reproduce

```powershell
$py = 'research-scale-100k\.venv\Scripts\python.exe'   # the only interpreter used
& $py research-phase01\data-work\scripts\structured\run_all.py           # rebuild all artefacts (~0 s, $0)
& $py research-phase01\data-work\scripts\structured\run_all.py --force   # re-call the API (~$0.09)
```

| script | role | rerun behaviour |
|---|---|---|
| `segments.py` | TOC parse + section splitting, title heuristic (scratch output only) | pure function of the markdown |
| `stage1_dishes.py` | 1 LLM call per section -> `vn_dishes.csv` | cache hit, $0 |
| `stage2_facts.py` | 1 LLM call per page chunk -> verify -> `culture_facts.jsonl` | cache hit, $0 |
| `stage3_db.py` | `DROP TABLE IF EXISTS` + load -> `facts.db` | idempotent |
| `stage4_report.py` | independent re-verification + `REPORT.md` | writes `cost.json` from the cache |
| `common.py` | .env key loading, cached chat completions, cost accounting, JSON repair | - |

Pitfalls worth knowing before touching this pipeline:

1. **cp1252 console.** Any `print()` of Vietnamese either mangles or raises `UnicodeEncodeError`. All scripts log ASCII only and write UTF-8 files; use `$env:PYTHONIOENCODING='utf-8'` if you must print.
2. **Concurrency + shared JSON state.** `cost.json` and the reply cache are written by up to 8 threads. Both are published atomically (temp file + `os.replace`) and reads tolerate torn files; before that fix, a torn read silently turned into a *new* API call and a different fact set on every rerun.
3. **The TOC pages are glyph-garbled but numeric.** Never trust TOC titles for anything but counting; use the printed page numbers as section boundaries and take titles from the body.
4. **`max_tokens` matters more than prompt wording.** The facts prompt overruns at 1.5-2k output tokens on a 5-page chunk; truncation produced unparsable JSON that used to be silently recorded as a chunk with zero facts.
5. **Never relax the substring check to 'close enough'.** The 81% pass rate is the price of honesty; the 19% that fail are mostly sentences split across a page break.
